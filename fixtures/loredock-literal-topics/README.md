# Task 073 — Fresh frozen literal-topic qualification

Freeze these inputs before implementing or observing the offline candidate. This owned
four-source parcel corpus, 35 structural variants and typed oracle are authored from source
bytes, not candidate output. They are known to the author and are not blind/external review.
Task 071 and all earlier exhausted matrices remain untouched and must not be rerun.

## Protocol

1. Commit this corpus, full per-case source replacements/deletions, oracle and protocol.
   Review the input bytes without running a path projection. Record the candidate's separate
   adapter/rule/schema namespaces. Develop only against unrelated small regression inputs.
2. Commit the final candidate and observer before the first frozen observation. Record full
   HEAD, input SHA-256 hashes, source-fork hashes, Node/hardware and an exclusive absolute
   output directory. Do not run other heavy checks alongside the matrix.
3. Execute once. Each structural variant gets a fresh owned catalog. Evaluate the unchanged
   production control and new candidate, journaling each exact compact projection immediately
   after return and before assertions. Compare explicit control expectations when supplied;
   record other controls without inventing success requirements. Never relabel a control
   miss as a new candidate failure or a deliberate dynamic abstention as useful-path success.
4. On every variant require available bounded projections, exact producer hash identities,
   full original text/range/content hashes, complete witness support and zero Git/catalog
   mutation outside explicit fixture lifecycle hooks. Positive cases must contain a delivery
   candidate and two paths ending at document writes; negative cases must contain no delivery
   edge. Require specified omission reasons. Unknown expressions may omit an operation at
   parsing, but must retain an explicit adapter/resolution gap and no heuristic delivery.
5. The default case checks every typed required identity, exact witness/environment, HTTP
   support, distinct reference/symbol roles and unchanged old answer/context/correction bytes.
   Repeated and selected-root captures must be stable. Walk all four-entry-point pages and
   select the isolated root beyond page one. Keep default path ordering separate from routing.
   Branch variants require counted alternate terminal paths and retained complete originals.
6. Exercise every reduced path bound in the oracle, cancellation at each path stage, every
   receipt bound (zero except source bound one), invalid/increased limits, cancellation at
   every capture stage and all listed capture-stage/mutation pairs. Require refusal or the
   documented bounded omission without partial/unsupported paths; zero comparisons yields
   no event edge, zero nodes/edges/flows yields no flows, one step yields at most one node.
   Rejected receipt work creates no new receipt/pending file. Also test an external committed
   write before the final guard and a blocked competing writer while its lock is held.
7. Each listed history case captures a complete receipt first, then applies its lifecycle
   change. Read history without path, fact, snapshot or Git calls or catalog DML. Eviction,
   restart and new publication preserve exact old bytes; revocation/policy/original corruption
   or a missing file refuses the whole read. Added sources make the old receipt stale without
   expanding its recorded dependencies. The alternative case adds the frozen same-name Java
   handler without changing old files: journal the new projection before checking that the
   old unique `implements` edge is absent. Old bytes and notes remain historical, not reapplied.
8. Corruption cases use the trusted recorded receipt ID or reseal the outer wrapper to reach
   nested validation. Preserve every edited artifact before asserting refusal. Changed topic
   value/expression/support/rule, missing/unexpected witness, unknown identity/schema, changed
   originals, missing dependencies and duplicate JSON keys must fail. No external import or
   authenticity claim is made.
9. Preserve first stdout/stderr/exit, raw receipts/projections/errors and all observations.
   Journal raw returned bytes before assertion/invariant/resource checks, including failed
   cases. Record prerequisites that prevent a later check as unexecuted. Continue independent
   cases after failure only when owned cleanup succeeds. No frozen candidate, oracle or run
   is retuned/repeated after observation; a failure requires a new prospective successor.

## Resource and publication rules

Measure each successful projection/capture/read using one outer operation clock, 5 ms timer
samples plus a final sample, baseline/maximum sampled RSS and heap growth. Require under
5,000 ms wall time, at most 150 ms maximum sampled interval, 384 MiB sampled process RSS and
64 MiB sampled heap growth. Keep existing path limits, 512 KiB complete projection, and the
receipt's 30 spans, 64 KiB originals, 640 KiB wrapper, twenty sources and one-million work cap.
No increased limits. Injected failures/waits are diagnostic, not resource success cases.
Sampling is not hard isolation, a peak-memory guarantee or maximum-inventory qualification.

Receipt publication retains a synchronous SQLite immediate lock with no DML around final
epoch validation and the owned content-addressed file handoff. Count fixture lifecycle writes
explicitly; do not exempt an entire operation from mutation accounting. History must reopen
exact originals and the full original authorization scope, including the uncited guide.
This is a local handoff experiment, not atomic crash recovery across independent resources.

Useful-path, support/safety, resource and observer-validity gates are all mandatory. A harness
error rejects the applicable gate. Passing this small structural family permits a separate
integration/scale review only; it does not switch consumers, transfer notes, grant semantic/
private-pilot acceptance or authorize a model call.
