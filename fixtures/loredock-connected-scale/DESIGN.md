## Input boundary

Twenty owned repositories contain README text, Vue/Dojo clients, literal routes, Java event
publication/subscription/write syntax and synthetic independent utilities/descriptors.
Half of the filler files contain one function and half contain a constant descriptor with
no supported function. This deliberately separates file-validation cost from fact density;
it is not a claim about typical projects. The pilot-specific `orderTopic` rule remains.

The catalog admits **10,000 paths total**, including non-code metadata, in fixed source
shares. Therefore the four base shapes contain 120/600/3,600/10,000 total files and exactly
95/575/3,575/9,975 code files. Every source has an equal total file count; critical code uses
late `z/` paths. Do not increase catalog limits to claim 10,000 retained code files. Generated
ordered file hashes, per-source counts/bytes and critical original line locators are frozen
in `baseline.json`. Changed variant bytes are independently hashed before observation.

The baseline default pair must contain all seven critical nodes, thirteen display nodes,
twelve edges and two write-ending paths. Original support and static/candidate/runtime
qualifications are mandatory. Root, path-ranking, tie-breaking, simple-path, ambiguity,
incomplete-source, header/topic/environment and atomic-admission semantics follow Task 063.
Explicit root selection chooses one supported root without changing the binding universe.

## Candidate work contract

Implement a separate offline candidate with indexed matching and cooperative checkpoints.
Use complete source/path/export and qualified/simple Java handler indexes, owner/operation
indexes and record/consumer indexes; preserve alternative order and all relevant alternatives.
The retained-fact scan and all resolution stages must complete before positive uniqueness.
No display/page slice may narrow the candidate universe. Keep the conservative incomplete-
source rule; do not infer uniqueness from truncated/missing alternatives.

Only the candidate file limit rises to 10,000. Retain 10,000 fact entries and 12,000 each of
resolution nodes, edges, binding records and alternative references. Keep 2,000 candidate
comparisons, two default roots or one requested root, twenty nodes per path, 1,000 traversals,
1,000 pending paths, 160 display nodes, 240 display edges and 512 KiB serialized display
envelope (including identity/coverage/limits). No full diagnostic vectors in that envelope.
Count at most 1,000,000 deterministic work units across reads, index inserts, scanned
alternatives, comparisons and path work; overflow discards the graph. Check work/cancellation/
current scope at least every 128 logical units and between file reads. Synchronous original
validation, bounded sorts, declaration projection and snapshot checks remain measured costs.

Use a five-second cooperative projection deadline. Check after the final yield and scope
fence; an over-time result cannot publish. Scope/cancel/integrity failure returns no graph,
retained payload, resolution vector or consumed source/evidence identifiers. Internal lowered
limits are supported for boundary checks. No source Git calls, model calls, SQLite writes,
analysis start or implicit retry occurs during a projection except declared lifecycle hooks.

## Measurement and decision

Run this matrix once after committing candidate/harness identity; output directory creation
must fail if it already exists. Save each observation immediately, including harness failures.
The only repeats are those listed above. Run no other heavy local checks concurrently with
the recorded projection measurements. Record hardware, Node, implementation hashes and
prepared inventory counters. Input preparation/indexing/analysis are outside projection time.

For every successful base S01–S04 observation, require projection wall time **<=5,000 ms**,
maximum timer delay **<=100 ms**, sampled process RSS increase **<=256 MiB**, total sampled
process RSS **<=1 GiB**, and sampled heap increase **<=128 MiB**. Use a 10 ms heartbeat;
include synchronous beginning/end work by arming it before projection and flushing after
completion. Sample at stage/checkpoint boundaries too. Report baseline, peak, after and
sample count. Samples can miss allocation peaks; these are one-machine observations, not
hard real-time or OS memory isolation guarantees. No forced GC or cold-cache claim.

Record per-stage wall times and maximum uninterrupted checkpoint interval in addition to
heartbeat delay. For all cases verify complete original span text/hash/revision/path/line
correspondence using independently generated bytes and Git tree blob hashes; reopening must
not incur projection Git calls. Record work counters, envelope bytes and zero read-side
mutations. Normalize generated catalog IDs only for cross-registration comparison; repeated
reads of one inventory must match exactly after removing timing/memory fields.

The gate requires every correctness/boundary check and all eight base resource observations.
Merely rejecting every large input does not pass. A failed assertion, resource threshold or
harness observation stays in the receipt and blocks promotion. Diagnose it without replacing
the first run or repeatedly tuning this frozen corpus. A successor requires fresh prospective
scope. Passing permits a separately scoped typed backend integration; it establishes neither
semantic answer quality, runtime connectivity, routing nor private-pilot acceptance.
