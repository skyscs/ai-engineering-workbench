# Frozen prepared-read qualification protocol

Task 091 measures Task 090's request-local prepared-read statements composed with
Task 088's compact entries and Task 081's streaming snapshot candidate. This fresh
greenhouse-calibration family is authored alongside independent full-process
integration and frozen only after it passes, before any application parser/candidate
observes it. Expectations follow source construction and adapter capability review;
this is not blind or private-project acceptance. No prior family is imported or rerun.

## Fixed execution

Use Linux Node 22.23.2 / V8 12.4.254.21-node.56 with no runtime flags or NODE_OPTIONS.
Verify frozen input/baseline hashes and a committed clean entry point before running.
Record hardware/runtime/implementation identities. Use one owned output directory.
Before execution, Task 090's exact implementation head must pass both push and
pull-request CI and merge with an identical tree. Freezing inputs does not waive
that requirement; record the accepted merge in the measured entry point's evidence.

Run **two arms, eight operations each**. The preparer indexes/analyzes, closes and
copies the stopped initial data, then reopens in its existing PID. A separately
launched reader starts from the exact unchanged initial-data copy. Each runs first,
three repeats, selected root, page four, isolated root, two replacement analyses and
history after eviction. The initial snapshot is verified before each dependent run.
A missing/invalid preparation blocks the second arm; a first-arm operation/cleanup
failure remains failed even if the independently verified initial copy allows the
second arm to contribute evidence. No operation or process is retried.

Use the unchanged generic uninstrumented Task 082 worker and unchanged Task 089 coordinator.
No profiler, heap snapshot, manual GC, phase/query/owner hooks or terminal helper.
Keep ordinary counters, aggregate work charges and the 5 ms outer resource sampler.
Expected-corpus construction and all assessment remain in the parent after child exit.

Application gates stay **5,000 ms**, **1,000,000 work units**, **150 ms** maximum
sampled interval, **384 MiB** sampled RSS and **64 MiB** sampled heap growth. Preserve
512 KiB projections, 640 KiB receipts, 64 KiB original text, 30 spans and 20 sources.
No output budget, source domain, original reread, ambiguity or final fence is removed.
The preparer watchdog is 900 seconds, reader 600 seconds and total 1,800 seconds;
TERM is followed by KILL after five seconds. A 1,830-second outer wrapper bounds
parent assessment/cleanup too. Metadata/worker JSON reads are bounded regular files
of at most 1 MiB; receipt/artifact decoding keeps the existing strict bounds.

## Assessment and first-result retention

Keep independent artifact/shape/source/usefulness/history/repeat/resource dimensions,
exact complete-path/span/scope results and no-write/work/output/hook observations for
all sixteen operations. A resource failure cannot hide other checks. Missing inputs
are explicit failures/blocks with fixed planned denominators. Compare exact first,
three repeat, selected, page and isolated bytes between arms (seven comparisons),
with no ignored fields; each history must match its recorded first receipt.

Every required dimension, both child lifecycles and all seven cross-arm comparisons
must pass. Save metadata, stopped-copy hashes, all raw returned wrappers/receipts,
worker/parent reports, stderr/stdout and normalized process exits. Preserve the first
result, including partial output, without oracle repair, limit increases, selective
replacement scores or a retry. All earlier failed scores remain unchanged.

Passing this synthetic qualification permits a separate production integration
review; it does not establish an independent/private pilot or L5 readiness. Failure
keeps the candidate unqualified and selects at most one evidenced next action.
Without a matched baseline arm this run tests fixed acceptance limits, not a causal
percentage memory improvement over an older differently shaped family.
