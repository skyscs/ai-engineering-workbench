# Prospective native question-context inputs

Task 119 freezes this fresh ordinary six-source library system for the offline comparison
in [Task 120](../../tasks/120-loredock-native-question-context-feasibility.md). Read the
[contract](../../docs/loredock/NATIVE_QUESTION_CONTEXT.md) before using it.
No candidate, baseline retrieval, parser, native resolution or model has been run against
these inputs. Importing the data-only factory to hash its exact file vectors is authoring
validation, not an experimental observation or a test pass.

- [corpus.mjs](corpus.mjs) creates base, overlapping-root, missing-consumer and dynamic-topic
  variants without importing application code, expected outcomes or existing corpora.
- [questions.json](questions.json) fixes seven question cases, typed path/support/scope
  requirements and eight boundary groups. The loan-return root follows six unrelated Vue
  roots, so browser defaults and the first root page cannot be the search universe.
- [freeze.json](freeze.json) records every source file's generated bytes/hash, each ordered
  file-vector hash, the five normative input/design hashes and sixteen audited production
  source hashes at accepted PR #122. It does not claim a compiled candidate runtime.

The source syntax uses familiar supported parser idioms, but names, topics, documentation,
questions and counterexamples are newly authored. This is agent-authored mechanical
relevance/support evaluation, not blind external or semantic assessment. The first frozen
run belongs to Task 120 after its independent development and concrete protocol freeze.
Do not tune this factory/oracle after candidate output, hide failed positive cases or reuse
an exhausted resource/model family. Old qualification artifacts remain untouched.

All material is owned synthetic text. The quoted instruction in untrusted-example.md is
explicit test data and grants no tool or network authority. No external source, account,
corporate repository, real model or user demo is required.
