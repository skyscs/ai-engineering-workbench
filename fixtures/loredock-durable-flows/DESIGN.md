# Prospective durable-flow comparison

Task 062; scope `b368729`, production base `7e8c921`. The Task 061 contract applies.
Freeze this generator, its complete generated file bytes/locators and independent support
oracle before prototype observations. This is an offline, known synthetic comparison,
not a blinded semantic evaluation. No real models, corporate sources or old receipt reruns.

Seven deterministic input variants are defined in `corpus.mjs`. The small baseline retains
five code files. Long-path adds 360 short-path functions (365 code files total); dense adds
one 200-function file (six); ambiguity adds a JS import alternative and duplicate Java
handler (seven). Topic and environment each change supported wiring independently (five
each); syntax-gap adds one malformed TS file (six). Every variant stays below 600 files.
The oracle records seven critical source-backed nodes, exact source literals/line locators,
seven edge-kind counts and two partial outlines reaching a document-write node for the
small control. It does not claim real dispatch, HTTP authority or database ownership.

Fixed cases:

- F01: small production / saved parity / wide, each first and one repeat. Ordered graph
  semantics (including original evidence, gaps, limits, omissions) must match in parity.
- F02: long-path, same modes/repeats; all critical facts must be retained. Record critical
  graph support and omissions even when wider selection cannot recover the end-to-end path.
- F03: dense, same modes/repeats; record original support lost to symbol admission.
- F04: ambiguity, same modes/repeats; both import targets and handler alternatives must
  remain visible in facts. No arbitrary calls/implements edge for the ambiguous targets.
- F05: separate topic/environment variants, same modes/repeats; HTTP stays candidate,
  unsupported import remains unresolved, contradictory/unbound delivery is not asserted.
- F06: fresh catalogs for absent inventory, paused unpublished inventory, reduced document
  budget of two, published syntax-gap inventory, and a deterministic zero reader-time cap.
  Missing parity payloads are unavailable; wider partial coverage preserves all counters.
- F07: separate fresh catalogs with checkpoint, payload, original, parser or limits damage.
  No graph/payload escapes a failed read. Never repair and hide the first observation.
- F08: separate fresh catalogs; after the first validated file/yield, add a fourth owned
  source, revoke a source, change policy, or evict the selected old inventory. All pending
  results must be discarded. Hook writes/Git calls are deliberate setup, counted separately.
- F09: two indexed revisions (second appends a source comment), both retained inventories,
  first/repeat reads, restart equality, then third inventory eviction. Old facts unavailable;
  saved originals and the old production control still reopen under unchanged authorization.

Use a pinned experimental copy of the production assembler with saved facts/ranges in
place of parsing and an explicitly different adapter/ID namespace. Canonical comparison
maps only generated graph IDs and excludes adapter/schema/input hashes; it retains every
semantic field, array order, original evidence ID, coverage and omission. Preserve byte and
graph caps; the wider input uses inventory order/limits, not a new production selection rule.
No endpoint or browser change. Read through CodeAnalysis, yield per file, cap reads at five
seconds and recheck the same manifest/policy/registry after scanning and before publishing.

Record complete file/fact/range/graph vectors, original reopen outcomes, generated source
hashes/revisions, implementation/fingerprint, serialized bytes, validation/assembly/reopen
and wall timing, sampled RSS, retained/scanned/missing units and every omission. Projection
makes zero Git calls and SQLite writes; lifecycle hooks are explicitly excluded and reported.
These are logical input/payload counts, not physical I/O or isolated performance benchmarks.

The prototype may fail a promotion condition. Preserve such results and reject the naive
wider policy when support is lost; do not change ranking, budgets, fixtures or oracles in
response. Harness defects require a separately recorded correction and retained failed
receipts. A successful parity result alone does not authorize a production switch.
