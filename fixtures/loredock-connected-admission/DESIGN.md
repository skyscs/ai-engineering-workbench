## Fixed policy

1. Validate one compatible published CodeAnalysis snapshot, all retained payloads and their
   complete originals, yielding per file. Recheck manifest/policy/registry before return.
   Cap the corpus at 600 candidate code files and the cooperative read/resolve operation
   at five seconds. An unfinished scan, integrity failure, eviction or scope change returns
   no graph or consumed source identifiers. No analysis starts as a side effect of reading.
2. Separate the resolution universe from display slots. Resolve supported pilot bindings
   using all retained symbols/operations. Preserve the existing named-import, handler,
   HTTP/header and record/topic/environment rules, including the pilot-specific `orderTopic`
   key; this is not a generic broker/configuration analyzer. Missing/nonparsed units or any
   syntax gap make their source incomplete. Do not issue unique calls/implements/consumer
   bindings for an incomplete target source. Other retained syntax can remain visible with
   explicit gaps. Unknown syntax outside the supported profiles is still not runtime proof.
3. Bound temporary work separately: at most 10,000 symbol/operation/call/record entries,
   12,000 resolution nodes, 12,000 resolution edges, and 12,000 binding records/target references each; exceeding these fails the whole
   candidate. HTTP/event pair comparisons remain capped at 2,000. Resolution nodes do not
   consume display slots. No hidden truncation may turn an ambiguous match into a unique
   one. Record full alternative identities in the diagnostic receipt, with bounded counts
   in the display result. Existing declaration-map coverage/budgets remain independent.
4. Use the existing root roles: Vue actions, then AMD functions, then HTTP-request functions
   with no resolved incoming named import. Sort ties by source name, path, symbol key and
   source ID using code-unit ordering. Select the first two root candidates, even if one
   has no outgoing edge. Count unselected roots. This is a navigation policy, not a claim
   that all repositories or incident roots fit in two outlines.
5. Enumerate simple paths from those roots, bounded globally by 1,000 traversals and 1,000
   queued paths, and by twenty nodes per path. Rank terminal paths by the existing score:
   a document-write ending receives 1,000 plus path length; others receive path length.
   Break ties by source/path/kind/label sequences. Choose one whole path per selected root.
   A root with no supported edges can produce a one-node partial outline. Disclose omitted
   roots, alternate terminal paths, truncated depth, pending work and unselected resolution
   nodes/edges; do not describe the two outlines as the complete system.
6. Admit each chosen path atomically, with all endpoint nodes, edges and complete original
   support. Keep display caps at 160 nodes, 240 edges, two outlines and 512 KiB, plus current
   label/property bounds. If the whole path does not fit, omit it with a reason; do not
   publish a half-path or silently choose a less-supported replacement. Keep auxiliary
   contract/topic/type/import support even when its declaration node is not on the path.
7. Use a separate experimental adapter and ID namespace. Preserve static/candidate/gap
   semantics and original evidence. No UI, answers, reviews, history or candidate consumers
   switch to this graph implicitly. Full resolution vectors are diagnostic data, separate
   from the bounded display response. Partial or failed readings never imply absence.
