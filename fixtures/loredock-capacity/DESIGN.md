# Larger synthetic capacity baseline — premeasurement contract

Use only owned generated sources. Preserve the existing twenty-source corpus and every
historical report. Freeze this contract, workload generator and manifest before the first
measured production index. No model calls, corporate code, remote cloning or product tuning.

## Workload

Derive a new owned corpus from the immutable twenty-source fixture: add 180 UTF-8 TypeScript
files of exactly 2,048 bytes to each source (3,600 additions, 3,679 eligible files total).
Use deterministic load/probe-NNNN.ts paths and unique literal loadProbe symbols. Files contain
ordinary source syntax and deterministic padding, never oracle assertions or instructions.
Commit the additions in each generated repository. The original commits remain ancestors;
original source bytes, paths and blob IDs stay unchanged while the derived revision vector
changes. Keep the sixty excluded canaries and all root README files. No generated file is run.

Record a stable manifest with every original/generated locator and revision. Keep generation
and registration durations separate from indexing. Three frozen exact-symbol questions
exercise the final added file in sources 0, 10 and 19; use the ten unchanged Task 035 incident
questions separately. Expectations stay outside source directories and product inputs.

## Execution

Run two fresh owned generations with the current production defaults. Each receives one
initial indexing attempt and, only if it publishes, one unchanged refresh. Do not enlarge
limits or automatically resume/retry paused/failed work. Preserve partial coverage and
unavailable queries explicitly. Two declared generations are reproducibility measurements,
not retries selected after looking at results. Remove only owned temporary fixtures afterward.

For each completed stage, record duration, source/file/byte coverage, retained raw/span and
checkpointed SQLite bytes, Git blob-read attempts and file reuse. Sample evaluator-process
RSS while indexing; child Git memory and operating-system cache isolation are not measured.
Record all current limits, versions and implementation provenance. These local timings and
synthetic syntax are diagnostic, not production service levels or realistic framework cost.

On published initial/refresh indexes, measure root README orientation and the thirteen fixed
questions. Keep source recall, reference availability, candidate counts, code/declaration
coverage/omissions and scope decisions separate. Verify every selected original against the
owned Git revision/blob/content/range/hash. Compare canonical selections across unchanged
refresh and both fresh generations, preserving any differences rather than changing rules.
The code graph's bounded document sample is not the whole indexed system. An unexamined
file is not proof that its behavior is absent.

## Acceptance and follow-up

The baseline succeeds as an engineering experiment when its provenance, limits and failures
are faithfully recorded; indexing/reference/selection shortfalls must remain visible. Keep
all previous semantic gates and independent/private-pilot requirements. No bridge or automatic
routing acceptance follows from indexing thousands of generated files.

Use focused generator/protocol checks in normal CI and keep the full-volume run explicit.
After recording the baseline, choose the smallest follow-up justified by observed evidence;
do not optimize product behavior in this task or rerun only to improve a recorded result.
