# Task 079 — Frozen memory attribution protocol

Freeze this file, `corpus.mjs`, `oracle.json` and `preflight.json` together before candidate
implementation. No parser, path candidate, catalog or diagnostic has observed these inputs.
The measured candidate and harness must also be committed before exactly one execution.

`corpus.mjs` is a pure generator for twenty owned library-loan repositories. Sizes
are 28 and 498 total paths per source: 560 and 9,960 total files, including 23 original
README/route/contract files and 537/9,937 code files. Every source fits its fixed share of
500 paths and 2.5 MiB. `preflight.json` records actual in-memory UTF-8 counts and hashes.

The intended useful chain is Vue action → named TypeScript HTTP client → declared Java
handler → literal event publisher → subscriber → Mongo document write. Four connected
actions and one isolated action place explicit selection beyond the default root page.
All twenty sources remain authorization dependencies, including an uncited handbook.
Constant-only marker files deliberately have no supported facts and retain syntax gaps.

Expected meaningful fact count is 21: five Vue symbols/calls (10), one TypeScript symbol
and HTTP operation (2), a publisher symbol/operation/record (3), and two subscriber
symbols/two operations/two records (6). These expectations come from source construction,
not parser output. This is agent-authored synthetic data with the same diagnostic shape, not blind or
independent semantic acceptance. Input text/identities and exact counts are new.

Tasks 075 and 077's failed gates, bytes and limits remain unchanged. No model or corporate source
is used. Preparing new bytes does not qualify an implementation or authorize promotion.

## Fixed execution

Run sizes in ascending order, each with three sequential arms. No concurrent heavy checks.
Use Node 22.23.2 without `NODE_OPTIONS`, heap flags or forced GC. The coordinator creates
one fresh exclusive output directory, records input/candidate/baseline hashes and hardware,
and supervises owned child processes. Each child writes stdout/stderr and incremental raw
results directly to durable files. Preserve every exit, including timeouts and cleanup errors.

For each size, the first child prepares the catalog once, samples before/after source/index
preparation and analysis, and records exact admitted paths, parsed files, fact expectations,
source revisions/tree IDs and preparation times. Preparation is outside operation thresholds.
Allow at most three explicit resumes of a paused/interrupted index or analysis under its
unchanged bounds; record each resume. No failed/aborted job retry or enlarged cap.

Stop all services, checkpoint/close SQLite, and require no live nonempty WAL. Copy the stopped
data directory into an immutable initial snapshot and two separate owned arm directories.
Hash every regular data file and compare all initial copies before opening. Reject symlinks.
Store ownership locks are copied only after release. Keep the initial snapshot and owned
sources until all arms finish; catalog paths still reference those same owned sources.
Never copy a live catalog or open the initial snapshot through application services.

The first child reopens its own stopped catalog and performs the same-process arm. Only
after it exits, launch one fresh process for the reopened arm and another for the control.
Record opening memory, logical inventory/source identity and catalog initialization changes
separately from read measurements. The fresh readers do not generate or retain a corpus in
their measured process; the coordinator validates originals from the frozen generator after
each child exits. This difference is part of preparation/observer attribution, not a claim
of a production fix. All arms use the same candidate and no semantic identity exclusions.

Per arm, execute the eight operations listed in the oracle: default capture; three repeats;
capture the exact `lend` root from the first response; read the root page at offset four;
capture its exact isolated `search` root; then history of the first receipt after two new
analyses evict its inventory. Record replacement analysis time/memory separately. Close
services and record closure. The control disables phase/query/owner instrumentation but
retains ordinary counters, independent aggregate charge sums and the 5 ms outer sampler.

The preparer watchdog is 900,000 ms; each fresh reader 600,000 ms; the entire run 1,800,000 ms.
On timeout terminate only the owned process group and record the timeout/exit. There is no
restart of a timed-out child. Missing preparation blocks dependent arms explicitly. Other
independent arms can continue only while their unchanged initial snapshots remain valid.

## Measurement and correctness

Keep the Task 075 shared-budget semantics, matching, originals, SQL, checks and yield cadence.
Reuse Task 078's repaired runner and Task 077's unchanged path/receipt/observer helpers
on these new inputs. The runner accepts injected service constructors and checks complete
SQLite/JSON source column values without comparing object prototypes. Unchanged producer/
accounting identities permit exact byte comparison. Record all imported code hashes.
The control omits phase/query hooks. Both earlier experiments stay exhausted and untouched.

Instrumented operations keep at most 64 phase records and 128 distinct SQL templates per
process. Aggregate prepare counts by template SHA-256, without parameters or an event log.
Record raw `rss`, `heapUsed`, `heapTotal`, `external`, `arrayBuffers`, phase timestamps and
known owner counts. Count retained payloads/metadata/consumed identities at explicit reader
sites; snapshot wrappers can report returned file IDs, not pretend to observe internal header
lifetimes. Unsupported ownership measurements are marked unavailable. Do not serialize full
objects to estimate allocation bytes. Per-file fact reads and queries add counters only.

Observe snapshot boundaries, metadata/facts/domains/resolution/admission/final validation,
receipt projection/originals/publication, operation start/end, history and preparation/open/
close boundaries. Record publication-after only after the final guard/check returns. Missing
required capture phases or overflowing instrumentation fails observer validity. Instrumented
history must record start/end and keep fact/path/snapshot deltas zero. No per-query memory
sample, trace string, changed query, cache, skipped validation or additional yield.

Journal exact return/error, receipt bytes, memory and counter observations before assertions.
Evaluate all resource thresholds independently of semantic checks after a successful return;
resource failure does not prevent typed/support validation. Refusal blocks only checks that
need its result; do not use an absent first response as permission to invent a root. Record
each blocked operation, observer error and cleanup failure. Exit 1 if any resource, integrity,
parity, observer, preparation or cleanup gate fails, while preserving independent outcomes.
Even exit 0 would complete a diagnostic, not qualify a production optimization.

For default/repeat captures require two write-ending paths, all required typed nodes, 21
facts and exact admitted metadata/code counts. Require five roots, ten complete originals,
all twenty dependencies and no cited handbook passage. Selected capture has one write-ending
path; isolated capture has one symbol, zero edges and one singleton flow, five originals,
and the relevant `unresolved-import` omission. The offset-four page must expose that root.
Every used evidence reference must match the complete saved original text/hash/range from
the source construction; event witnesses retain both literal values and full support.

Compare repeat receipt bytes exactly within each arm. Compare all initial capture receipts
and root-page projection bytes across arms exactly; no semantic fields are ignored. Validate
history against its first saved receipt after confirmed eviction, with no nested fact/path/
snapshot/Git work. Selected required typed nodes are explicitly listed separately from
default nodes; validators must not special-case a fixture filename. Check operation Git/store-write/changed-row deltas and legacy row hashes.
Any deliberate replacement analysis is outside those no-write intervals and is labeled.

## Stop rule

Preserve the first complete run, raw artifact hashes and observations, including failed
resource gates and independently evaluated semantic results. Do not retune, selectively
rerun, collect until memory falls or replace samples with a different process lifecycle.
The outcome can leave allocation attribution uncertain; then scope one targeted profile.
Only measured attribution may select a later bounded optimization, which still needs a
new uninstrumented qualification. Old failures, user acceptance and model budgets stay intact.
