# ADR 0058 — Qualify question-selected native context before answer integration

Status: prospective offline design, Task 119, 2026-11-04. Production behavior is unchanged.

## Context

Native paths now have bounded reads, catalog-owned receipts, recorded browser history and
authorized discovery. Ask Project still consumes synchronous lexical retrieval and the
legacy bounded HTTP-comparison graph. The two default paths and four root cards cannot
select relevant context for a system-wide question. A saved receipt is historical static
context, not automatic current knowledge.

ADR 0050 requires question selection over complete bounded resolution and complete
already-issued original support before model exposure. Existing answers preserve immutable
input hashes, source/review dependencies and legacy adapter validation. Their synchronous
preview/start and recomputation at publication are not an asynchronous native preparation
or immutable native-witness lifecycle.

## Decision

Follow the [native question-context contract](../loredock/NATIVE_QUESTION_CONTEXT.md).
First compare one question-selected path offline, leaving literal retrieval, original
span order, engineer notes, legacy header clues, public consumers and production prompts
unchanged. The candidate selects from the complete native resolution through exact
supported identifiers/literals, admits no root on ambiguity, and requires every original
for a compact whole path to be already issued. Missing support or size overflow omits the
whole derived item; it never expands retrieval or removes source text.

Use one actual complete preparation budget, owner and source/identity fence. The current
30-span / 64 KiB text, shared six-item / 8 KiB derived allowance and 96 KiB complete prompt
limits remain. Raw receipt/projection and compact-input identities are distinct. Preserve
candidate, environment, missing-binding, branch and deployment limitations.

A new offline composition is explicitly identified and compared with actual public reads.
It is not a new public schema, a resource qualification transfer or a model evaluation.
Freeze the fresh six-source fixture, questions, support/scope expectations and stop rules
before candidate implementation. First failures remain visible and frozen matrices are
not rerun after tuning. Do not revisit exhausted model/resource families.

## Consequences

A pass may justify a separate production-preparation design. That design must reserve
asynchronous ownership before work, bind preview/start to one immutable input, retain a
trusted witness across inventory eviction, preserve old optional fields and source purge,
and validate the issued derivation without recomputing current paths at model completion.
Do not automatically create user-saved receipts on preview or guess durable retention now.
Schema changes depend on that future owner decision; none are required by this design.

Explicit questions about recorded history, automatic repository routing, new correction
namespaces, retrieval expansion and Workbench integration remain separate. A mechanical
pass does not establish semantic usefulness, private-pilot acceptance or L5 readiness.
