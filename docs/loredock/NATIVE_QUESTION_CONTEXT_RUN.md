## Fixed ledger and lifecycle

The [protocol ledger](../../fixtures/loredock-native-question-context-run/protocol.json)
contains 44 required observations: seven actual-retrieval questions and 37 boundary
observations covering the eight normative boundary groups. No denominator may disappear
when setup, selection, retrieval or an earlier operation fails. A blocked/unexecuted
observation is recorded and rejects the complete comparison.

The explicit observed entry point must refuse an existing output directory, verify the
normative freeze, this protocol and exact candidate/runtime identities, and journal an
exclusive start record before importing the frozen library factory. Freeze the completed
entry point/candidate/assessor and reviewed runtime identities before this sole run.
Use an owned process with a five-minute coordinator watchdog, a five-second cooperative
operation budget and explicit stop/close handling. Retain stdout, stderr, exit/signal,
raw results and stopped synthetic catalogs; no rerun or directory overwrite. A failed
preflight before factory import is not a candidate observation, but its log remains.

Use four distinct prepared catalogs for the four source variants. Setup indexes committed
owned files and explicitly runs ordinary code analysis; record counts, revisions, catalog
IDs and real parser fingerprints. Boundary cases receive independent stopped copies or
fresh owned setup so one mutation cannot silently change a later question case. Do not
index or reanalyze during a preparation operation. Closing catalogs must release every
owner, checkpoint live WAL and preserve source Git HEAD/index/working-tree state.

Each question retains the actual unchanged lexical baseline and current public default
path as independent controls, then measures the candidate's complete operation, including
its own actual lexical retrieval. This fixed ordering is a warmed-process comparison;
it is not cold-start or broad resource qualification. Controls may fail usefulness; they
may not supply the candidate with oracle choices or preselected root IDs.

## Offline composition and accounting

Keep all production modules unchanged. If the existing private producer cannot expose
its full resolution, preserve an explicit copy of the accepted producer source and a
small reviewed selection-only candidate delta, with deterministic emitted/import-relocated
bytes. All remaining runtime helpers must be actual compiled application modules. Record
both source/runtime identities and validate the delta against the retained control; no
claim that this driver is the unchanged production entry point or its operation owner.

The candidate has its own bounded request owner, cancellation and shutdown. It performs
one native resolution/read per preparation with one actual shared OperationBudget created
before lexical retrieval. No public root-page loop or per-root budget reset is allowed.
Use the existing typed resolver, admission, original authority and native receipt codec;
retain all final scope/inventory checks. Producing a receipt for assessment does not
publish it to the catalog's user-saved history or take a publication lock.

Instrument the baseline phase's actual returned SQL rows and reopened original UTF-8
bytes under that same budget. Record each charge class and its total; native phases use
their existing charges. Keep a separate outer wall clock and five-millisecond event-loop/
memory sampler with a final observation. Work/time are fixed gates. RSS/heap/event-loop
values are finite raw observations here, not new near-limit resource-qualification scores.
Do not remove synchronous baseline time, garbage collection or observer overhead from the
reported outer operation. No forced GC, smaller corpus substitution or hidden retry.

All source/store/fact/path/original counters and legacy answer/correction row hashes are
retained before/after. Preparation itself performs zero source Git, SQL mutation, automatic
analysis, user-history publication or model/network work. Controlled boundary mutations
are tagged separately in the fixture's async context; retain global deltas and the exact
injected deltas, rather than claiming their writes never occurred.

## Boundary controls

- `support.missing-original`: take a valid independently hashed actual source context,
  remove one required issued original, and assert whole-native-item omission. No replacement
  span or partial native path is admitted. Label the controlled input separately from the
  seven actual-retrieval questions.
- `budget.derived-size` and `budget.prompt-size`: use actual authorized originals and
  saved engineer notes to construct a valid controlled near-cap context. Additional
  padding passages belong to separately declared owned boundary setup, not edited frozen
  question files. Choose a bounded deterministic maximal fitting subset before native
  admission; preserve all its original bytes/order and notes. Assert whole-item omission
  at the existing aggregate 8 KiB derived / 96 KiB complete-prompt limits, with no raised
  production cap. Record the exact padding/subset algorithm and source hashes before
  running the matrix. Controlled fit observations do not count as retrieval improvements.
- `identity.foreign-build` and `identity.foreign-source`: same text/labels under a distinct
  real indexed identity cannot satisfy a required original. Rehashing a controlled context
  is not authority to mix identities. Refuse or omit before accepted native output.
- `inventory.missing`, `inventory.incompatible`, `inventory.evicted`: respectively no
  analyzed inventory, a genuinely different archived compiled parser fingerprint, and
  ordinary two-inventory replacement. Do not spoof a fingerprint or silently use the latest
  inventory/history. No automatic analysis is allowed inside the attempted operation.
- `freshness.registry` and `freshness.published`: actual source addition and a newer
  published index make the requested current preparation stale. Return no mixed vector.
- `policy.*`, `revoke.*`, `cancel.*`: inject at the first actual lexical, metadata, read,
  resolve, admit, originals and handoff checkpoint. Revoke the undisplayed operations
  source. The final handoff check and output remain synchronous after the hook returns.
  Expected source/cancel domain errors are retained; a private harness exception cannot
  pass as a successful fence. No partial accepted input or automatically restarted work.
- `lifecycle.busy`, `lifecycle.shutdown`, `lifecycle.work-zero`, `lifecycle.time-zero`:
  genuine occupied owner, active stop and trusted internally reduced budgets refuse output
  and release ownership. There is no client-supplied limit or HTTP change.
- `witness.inventory-replaced` and `witness.context-unchanged`: retain an issued native
  receipt/compact input, replace current inventories and revalidate its exact original
  support/source scope without facts or rederivation. Original context/notes/legacy rows
  remain byte-identical. This is offline witness evidence, not implemented production
  answer publication or durable retention.

## Assessment and stopping

The candidate imports no oracle. The independent assessor reads raw artifacts first and
matches required nodes by source/path/kind/label, not coincidental IDs or display position.
It validates exact original ownership, typed edges and all six dependencies, candidate/
partial status, literal witnesses, omissions and useful source bounds. Retain default,
baseline and candidate failures separately. Context and receipt hashes are integrity
checks, not independent semantic authority.

Freeze concrete padding controls, emitted candidate/control identities and the final
44-case driver before the observed run. Development uses separate disposable permit-based
inputs and can fix its first harness failures with retained logs. Ordinary CI must never
import the frozen library factory to score the reserved matrix. A frozen question failure
or interrupted attempt rejects promotion and leads to new prospective scope; no tuning
and rerun of the same observed matrix. No model budget or production consumer is enabled.
