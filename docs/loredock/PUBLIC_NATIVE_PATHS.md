# Native connected paths in the public application

Task 115 connects the existing `/api/code-paths` and `/api/code-paths/roots` routes and
**Browse connected paths** screen to actual CodePathsV2. Startup injects one explicit
owner, requests propagate abort signals, and shutdown stops paths before analysis and
catalog storage. The app factory also uses v2 when constructing its default reader.
There is no v1 fallback, generation relabel or experimental adapter in application code.

Responses expose native envelope/display versions, topic rule and shared accounting
identity. Matching direct Java topic literals appear beside candidate Kafka connections;
dynamic expressions retain an explicit gap. Original citations, selected roots, four-entry
pages, unavailable coverage, race handling and source/policy fences retain their existing
workflow. The browser rejects an unexpected envelope version and clears the pending view.
No extra user setting is required.

HTTP maps actual shared-budget cancellation/time/work outcomes to bounded 409 errors.
Unknown internal capability/observer failures retain the generic 500 envelope. The
existing host/origin/session/CSRF boundary and no-store responses remain. GET performs
no source/Git/legacy write and creates no receipt or receipt-storage layout.

This is a live derivation from a selected saved index. Static candidates, unknown runtime
behavior and deployment coherence remain explicit. A historical index is still labeled;
old parser inventories require explicit analysis, and a v1 generation cannot select v2
content. Saved path history is a separate later workflow, not implied by these reads.
