## Browser observation correction

The earlier sampler read only `/proc/PID/task/PID/children`. Linux exposes children per
thread, so a browser child created by another thread could be absent from the sum. The
new [passive sampler](../../../scripts/loredock-prepared-flow/process-tree.mjs) enumerates
every thread's child list, deduplicates process identities, checks parent/start identities,
and records per-process RSS, OS high-water RSS and raw user/system CPU ticks. This host
reports 100 clock ticks per second. Missing processes, vanished threads, changed ancestry
or missing memory counters are explicit incomplete samples, not a silent zero-byte pass.

The [subprocess regression](../../../scripts/tests/loredock-process-tree.test.mjs) creates
a real child from a Node worker thread. It confirms the child is absent from the leader's
child list, present in the full census, and included in the RSS sum. Negative controls
reject a mismatched root start identity and mark a stopped root as incomplete. No
process-name lookup or unrelated process termination is used.

An actual Chrome desktop/390px control completes one controlled answer and the real
review UI, retains screenshots and all raw process/network observations, and exits with
no owned survivors. Its 39 samples contain 37 edges originating from nonleader threads,
up to thirteen live processes and no reported sampling races. The maximum sampled sum is
**1,354,678,272 bytes**, above the unchanged prospective **1,073,741,824-byte** ceiling.
This functional control overlapped ordinary repository checks and is not a qualification
resource run. Earlier browser results keep their old collector and its limitation; no
historical measurement is recalculated or relabeled.

This is a sequential sampled live census, not a continuous or atomic process boundary.
Children that exit or reparent before observation may escape it. Final qualification
still needs complete lifetime attribution for browser descendants, including early
orphaning, alongside the external owner's termination/retention guarantees. A recorded
`complete` sample means its observed reads completed, not that no short-lived process
existed between samples. Sampled OS high-water values do not recover an exited process's
unobserved lifetime peak.
