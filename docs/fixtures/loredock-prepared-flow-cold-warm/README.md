# Cold entry and fixed warm flow controls

The [case helpers](../../../scripts/loredock-prepared-flow/cold-warm-cases.mjs) exercise
the actual production entry for a fresh source index, compatible code analysis and a
useful native review. Complete stopped checkpoints feed a separate controlled bootstrap
that performs exactly three sequential Find-review-admit-publish-history lifetimes.
Only its existing TextRuntime constructor is replaced. No provider or model executes.

Each completed warm lifetime retains the reviewed originals, actual prompt/schema,
published answer, saved answer and list response, per-call runtime counts and its entire
elapsed HTTP lifetime. The real worker must drain between repetitions. Issued original
IDs constrain the schema and answer citations; stopped witness prompt bytes, reviewed
hashes and context must match the actual request/review. The source checkpoint remains
unchanged. There is no best-of-three selection or retry.

The passive daemon journal is independently checked from startup through normal exit.
Its sampled RSS, OS high-water RSS, heap and full raw timer gap are compared against the
unchanged frozen ceilings. The nominal ten milliseconds is not subtracted from a gap,
and the final OS peak is included. Missing, failed, reordered or malformed lifetimes
cannot become passing measurements. These four checks are a subset of the full resource
assessment; even passing them never grants qualification.
