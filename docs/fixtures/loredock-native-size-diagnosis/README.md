## Compatibility decision

Do not silently alter `native-question-item/1` or its prompt. Tuple/header references
and the implicit outer binding change the wire interpretation. Current witness and
history readers accept only the current prompt version; changing that constant alone
would break old saved answers, including metadata-only history from Task 131.

[Task 133](../../../tasks/133-loredock-native-context-factoring.md) therefore owns a
separate versioned implementation. It must preserve v1 saved bytes and prompts, select
the matching validator by stored version, reject unsupported or inconsistent versions,
and resolve references identically in both Ready and saved-answer displays. Native
IDs remain non-citations, all originals stay explicit, and legacy source context stays
unchanged. No evidence, gaps, branch omissions, deployment uncertainty or topic/header
qualifications may be dropped to fit the budget.

Before implementation, declare fresh ordinary baseline/positive/boundary controls and
capture the complete synthetic snapshot through an explicitly owned diagnostic path.
That snapshot may support diagnosis; actual production HTTP must establish the useful
new path. The consumed reserved family and old run remain closed. A threshold increase,
unversioned format edit or removal of the unrelated but authorized legacy comparison
is not justified by this result.
