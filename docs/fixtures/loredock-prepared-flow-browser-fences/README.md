# Independent browser review and revocation fences

The [case functions](../../../scripts/loredock-prepared-flow/browser-fence-cases.mjs)
consume verified stopped copies of the earlier ordinary cold and successful-replay
checkpoints. The [ordinary entry](../../../scripts/loredock-prepared-flow/browser-fences-development.mjs)
runs preparation/review, history/review and history/revocation separately, with no new
answer admission. Their recorded source locations belong to the prior synthetic permit
control. The reusable functions accept checkpoint/question/source-name inputs; this
local development entry deliberately binds its previously retained input paths.

Each case uses the compiled browser UI and a declared CDP hold of actual response bytes.
The shared browser-case owner now accepts verified single-answer history as well as an
empty catalog; existing R08 functions keep their empty-catalog requirement. It checks
the saved history response against its checkpoint hash before opening Chrome. Fault
provenance remains explicit across every copy and launch. All runtime counters start
and finish at zero, and no model is invoked.
