# Workspace and AI connection settings

Open the local UI and choose **New workspace**. Enter a workspace name and a
connection label, then select the current CLI configuration or a named profile.
Optionally enter an absolute Codex executable path. Saving creates the workspace
and its connection together. Select a workspace to rename it, edit its connection,
or add, edit and delete model profiles.

The **Configured · not verified** badge is deliberate: these are saved settings.
This iteration does not run Codex or validate authentication, provider identity,
profile existence or model support. Authentication stays in the existing CLI
setup. A model profile may leave model and effort unset to request CLI defaults;
the Workbench never substitutes another connection or model after an error.

Each workspace owns one connection. Model profiles cannot be shared across
workspaces. Launch settings are editable until the workspace's data boundary is
locked; the first-task integration will be added in Task 006. An unlocked
workspace without repository records can be deleted after confirmation, removing
its connection and profiles. Task 004 blocks deletion when repositories exist;
see the [repository guide](repository-registry.md).

**Refresh** reconnects the UI after a daemon restart and reloads saved settings.
Failed writes are not retried automatically. If a change was saved but a following
refresh failed, the UI says so; refresh before submitting another mutation.

## API

All routes below use the existing local API session. Mutations require the exact
local Origin and `X-AEW-CSRF` token. Requests with a body require
`Content-Type: application/json`; streamed bodies are limited to 16 KiB. IDs are
generated by the server, and unknown input fields are rejected.

| Method | Route | Result |
| --- | --- | --- |
| GET | `/api/workspaces` | `{ workspaces: Workspace[] }` |
| POST | `/api/workspaces` | Create workspace and owned connection; return detail, 201 |
| GET | `/api/workspaces/:workspaceId` | `{ workspace, connection, modelProfiles }` |
| PATCH | `/api/workspaces/:workspaceId` | Rename workspace; return workspace |
| DELETE | `/api/workspaces/:workspaceId` | Delete unlocked workspace and settings, 204 |
| PUT | `/api/workspaces/:workspaceId/connection` | Replace editable connection settings; return connection |
| POST | `/api/workspaces/:workspaceId/model-profiles` | Create owned model profile; return profile, 201 |
| GET | `/api/workspaces/:workspaceId/model-profiles/:profileId` | Return owned profile |
| PUT | `/api/workspaces/:workspaceId/model-profiles/:profileId` | Replace editable profile settings; return profile |
| DELETE | `/api/workspaces/:workspaceId/model-profiles/:profileId` | Delete owned profile, 204 |

Workspace creation body:

```json
{
  "name": "Payments",
  "connection": {
    "name": "Corporate Codex",
    "executablePath": null,
    "configProfile": "company_gateway"
  }
}
```

Connection PUT accepts the same three fields as `connection` above. Workspace
PATCH accepts only `name`. Model profile POST/PUT body:

```json
{
  "name": "Investigation",
  "modelIdentifier": "company/router:model-v2",
  "reasoningEffort": "medium"
}
```

Optional settings default to null when omitted, including on PUT. See
[ADR 0006](decisions/0006-workspace-connection-ownership.md) for field limits and
ownership decisions. Errors use `{ error: { code, message } }`: invalid settings
return 400, missing or foreign profiles return 404, and locked-boundary changes
return 409. Existing session/security checks can return 401 or 403.

## Browser verification

After `pnpm build`, with Node 22.23.2, Google Chrome on Linux and port 4242 free:

```bash
node scripts/workspace-smoke.mjs
```

The opt-in script creates isolated application data and a fresh browser profile
under a temporary directory. It uses Chrome's `--no-sandbox` flag and opens only
the local fixture UI. It tests workspace/profile creation and edits, rename,
production-to-development daemon restart with persisted metadata, a 390px
viewport, and the deletion confirmation/cancellation paths. It leaves a JSON
result and desktop/mobile screenshots for inspection, then stops its processes.
No AI invocation or normal application data is used. The recorded local run's
[result](fixtures/workspaces/browser-result.json) is retained without temporary
paths, cookies or browser profile data.
