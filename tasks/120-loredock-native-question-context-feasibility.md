# Task 120 — Compare native question context on frozen owned inputs

Status: scoped by Task 119. Start after Task 119 exact-head acceptance.

Implement the smallest offline candidate and independent assessor specified by
[the contract](../docs/loredock/NATIVE_QUESTION_CONTEXT.md) and
[ADR 0058](../docs/decisions/0058-loredock-native-question-context.md). No production app,
retrieval, answer prompt/schema, source policy, parser, saved history or runtime setting
changes. Import no exhausted model/resource family and dispatch no model.

1. Verify the committed fixture/question/generated-vector hashes and source audit. Freeze
   concrete subcase IDs, operation accounting and the one-run coordinator protocol before
   executing the reserved comparison. Develop the runner on separate disposable inputs;
   those runs are development evidence and cannot replace the frozen comparison.
2. Reuse actual emitted native resolution/admission/codec helpers in an explicitly
   identified offline composition. Record all imports/copied orchestration and preserve
   actual public reads as an independent control. Do not repeatedly read roots/pages,
   reset work limits or pretend a modified driver is the unchanged production producer.
3. Start one actual budget before ordinary lexical retrieval. Select from the complete
   resolution, revalidate complete already-issued originals and all dependencies, fit a
   separately versioned compact whole-path item, then synchronously fence output. Preserve
   baseline spans/order, notes and legacy header comparisons. Disclose missing support,
   ambiguity, incomplete wiring and every output/budget omission.
4. Retain raw baseline/default/candidate/receipt/compact outputs before independent
   assessment. Check typed nodes/edges, exact source support, useful source bounds, all
   seven questions and every boundary group. Measure actual complete work/time, memory,
   event-loop observations, original/SQL/fact/path reads, writes and lifecycle cleanup.
   Temporary input/setup writes are distinct from the read-only preparation operation.
5. Run the frozen matrix once. Preserve first failure, interruption and unavailable
   denominators; never repair an oracle after observing the candidate or rerun to create
   a pass. Separate functional, relevance/support and resource judgments. A failed
   required case blocks promotion and leads to a new prospective scope.

The two positive questions must recover the late return path with at most three path
sources and complete original support already present in actual retrieval. The default
browser path is only a control and may fail those useful conditions. An expected
abstention/partial result is successful only with its required limitation and no invented
hop. Controlled support/size mutations are separately labeled boundary cases, not improved
retrieval outcomes. Complete six-source dependencies include the undisplayed source.

A passing offline result does not enable production answers. Scope the next preparation/
witness lifecycle and parity design, including immutable preview/start/publication,
review/source fencing, retention and old-input compatibility. No silent current/history
mixing, auto-save side effect, legacy-note transfer or L5/Workbench claim is permitted.
Keep raw artifacts, exact command/runtime identities, self-review, strict checks and both
exact-head CI outcomes before merge.
