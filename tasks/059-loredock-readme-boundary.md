# Task 059 — Twenty-repository README navigation boundary check

Status: scoped before implementation, 2026-11-01.

Task 058 delivers source-backed section navigation and a three-source browser check.
Measure the existing projection at its twenty-source README/input/span bounds before
building broader glossary or synthesis features. This is repeatable deterministic
engineering verification, not a fresh model benchmark or semantic acceptance gate.

## Prospective contract

- Generate a fresh owned twenty-source scale fixture; replace each root README in that
  temporary copy with an independently specified 32,768-byte, 960-line document. Keep
  baseline fixtures, consumed evaluation receipts and frozen outputs unchanged.
- Each README has twelve accepted 160-UTF-8-byte labels, nested sections and spans crossed
  at lines 119/121, 240/241 and later boundaries. Four additional recognized headings
  exercise output-count, empty-label and oversized-label omissions. Fenced/commented
  apparent headings are outside the outline. Record explicit expected lines, levels,
  ends and original 120-line-part ranges independently of the production selector.
- At the full 655,360-byte README input budget, require all twenty repository contexts,
  240 exact sections, 80 omitted labels and 160 issued original references. No manifest
  may displace a root README. Manifest omissions remain visible, not silent success.
  Check every label against its original line and every section's complete overlapping
  references against the selected source/revision/build. Keep output below 512 KiB.
- Measure the first projection plus two identical repeats, recording latency, output
  bytes, document count, original evidence calls, Git calls and SQLite total_changes.
  Correctness requires stable projections, zero Git calls and zero SQLite writes.
  Latency is descriptive; a first projection above one second triggers analysis before
  further orientation features, without changing the oracle or tuning frozen datasets.
- Publish an unchanged refresh and verify complete file reuse, stable logical section
  vectors with newly scoped evidence, historical identity and repeatability after restart.
  Check repository heads/worktrees and failed-attempt/model tables remain unchanged.
- Add ordinary regression coverage for the independently authored corpus/range checks;
  retain the compiled measurement, raw source hashes, runtime/implementation identity
  and negative observations. Do not introduce product behavior or parser/prompt changes.

## Delivery and isolation

Commit scope and implementation before the compiled measurement. Build in an owned
worktree; never restart/migrate the user's running demo or replace its compiled assets.
No browser rerun is required because UI is unchanged. Run appropriate strict/full checks,
review artifacts, publish a separate PR and merge after both exact-head CI events pass.
The result qualifies this constructed boundary shape only; real documentation quality,
large-project wall time and the private pilot remain open.
