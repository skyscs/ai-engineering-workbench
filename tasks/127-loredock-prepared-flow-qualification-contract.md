# Task 127 — Freeze prospective complete prepared-flow qualification

Status: scoped by Task 126; start after its exact-head acceptance.

The protected experimental browser flow is implemented, but its complete composition
has no resource or semantic qualification. Before changing the ordinary answer pilot,
freeze a fresh, bounded evaluation contract and owned inputs. This task is design and
input preparation only; it does not execute a qualification or make model calls.

1. Audit the exact daemon/browser/runtime composition and end-to-end lifetimes: source
   registration/indexing/analysis, preparation, scalar polling, review serialization,
   admission, all three witness validation boundaries, provider completion, answer
   listing/history, cancellation, restart, inventory eviction and dependency purge.
   Include actual HTTP serialization, client state and stored-history amplification.
2. Define representative twenty-repository and near-limit resource cases on a fresh
   owned corpus. Choose explicit useful outputs, maximum work/deadline/memory/event-loop
   and response/storage thresholds before observations. Separate warmed measurements,
   cold startup and complete worker/browser lifetimes. Include capacity/refusal behavior
   and the twenty-row answer list; do not infer aggregate bounds from per-phase budgets.
3. Freeze an independent source-grounded question/oracle set with cross-repository Java,
   JS/TS, Vue/Dojo, Kafka and Mongo examples within supported adapters. Include unanswerable
   and ambiguous questions, missing originals, legacy/native duplicate clues, source-only
   omissions and engineer review. State required qualifications and forbidden claims.
   Distinguish exact supported anchors from general natural-language understanding.
4. Bind source bytes, parser/app/provider versions, actual emitted imports, browser assets,
   expected originals, mode/settings, reviewer role and evidence retention before running.
   Reserve and exhaust new families exactly once. Never recycle an observed family or
   transfer the old resource/model gates. No corporate or prepared-demo data is permitted.
5. Specify separate future execution stages: model-free full resource/lifecycle qualification
   first, then a separately budgeted semantic run through the actual prepared flow only
   if its prerequisites pass. Freeze one-run failure/stop rules and preserve every failed
   result. Existing authorization for personal controlled CLI runs does not justify an
   unbounded or automatic model retry; model identity/account configuration must be explicit.
6. Record practical limits and a go/no-go rule for replacing the ordinary opt-in pilot
   input. Mechanical citation resolution, browser success or author scoring alone cannot
   establish incident-routing quality, complete system comprehension or independent L5
   acceptance. Keep the Workbench bridge and broader retrieval changes separate.

Deliver one reviewable contract and frozen inputs, with appropriate input/static checks,
then require both final-head CI events before the separately scoped execution task.
